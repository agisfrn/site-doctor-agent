# Site Doctor v2 — Design

Date: 2026-10-29
Status: approved in conversation, pending written-spec review

## Goal

Turn the single-file Site Doctor prototype (`site_doctor.py`, 167 lines) into a polished, pip-installable
CLI that works as a GitHub portfolio project. Visitors judge it from the README, so a demo GIF, a report
screenshot, clean code, tests and CI matter as much as features. It must stay easy to demo live.

Stack stays: Python, the Anthropic API (tool use), Playwright.

## Decisions

| Decision | Choice |
|---|---|
| Shape | Polished CLI tool (not a web app) |
| Checks | Basics, links, accessibility, SEO, performance, security, mobile — all of them |
| Architecture | **Hybrid**: Claude steers the crawl; deterministic code runs every check; Claude explains and suggests fixes at the end |
| Severities and scores | Rule-based in code, never chosen by Claude, so they're identical across runs |
| Model | `claude-opus-5-5` by default, `--model` to override; effort `medium` by default, `--effort` to override |
| Python | >= 3.11 |
| License | MIT |

## Components

### browser.py
`Browser` owns one Playwright browser and a desktop context (1280×800). A mobile context
(390×844, phone user agent, touch) is used when mobile checks are enabled.
`capture(url) -> PageCapture` loads the page and records:
- final URL, HTTP status, response headers of the main document
- title, HTML, links (`a[href]`, absolute http/https), images (src, natural/rendered size, bytes)
- console errors and uncaught page errors
- every network response (URL, status, type, size, scheme) for page weight and mixed content
- performance timings via `PerformanceObserver` (LCP, CLS) and Navigation Timing (TTFB, load)
- axe-core results (axe injected with `add_script_tag`, run with `axe.run()`)
- mobile data, when enabled: document width vs viewport width, tap targets smaller than 24×24 CSS px

`check_link(url) -> int | str` does a GET through the context's request API (status code, or an error string).
`screenshot(url, path, mobile=False)` saves a full-page PNG.
Failures raise `PageLoadError` with a short message.

### checks/
Each module exposes `check(capture: PageCapture) -> list[Finding]`. They're pure functions of the capture,
so they can be tested without a network. Site-level checks (robots.txt, sitemap.xml) live in `seo.py` as
`check_site(origin, fetch) -> list[Finding]` and run once per scan.

| Module | Findings (severity) |
|---|---|
| basics | page 5xx (critical), page 4xx (high), JS error (high), console error (medium), missing/empty title (medium) |
| links | broken internal link (high), broken external link (medium), unreachable host (medium) |
| accessibility | axe impact critical→critical, serious→high, moderate→medium, minor→low |
| seo | missing meta description (medium), no/multiple h1 (low), missing canonical (low), missing OG tags (low), missing robots.txt / sitemap.xml (low) |
| performance | LCP > 4s (high) / > 2.5s (medium), CLS > 0.25 (high) / > 0.1 (medium), TTFB > 800ms (medium), page weight > 3MB (medium), image > 500KB or >2× its rendered size (low) |
| security | not HTTPS (critical), mixed content (high), missing HSTS on HTTPS (medium), missing CSP (medium), missing X-Content-Type-Options (low), missing frame protection (low) |
| mobile | horizontal scroll (high), missing viewport meta (high), tap targets < 24px (medium) |

`Finding`: `id` (stable rule key, e.g. `security.missing-csp`), `category`, `severity`, `title`,
`url`, `evidence` (short string), `screenshot` (optional paths).

### agent.py
Manual tool-use loop over `client.beta.messages.create` with the `server-side-fallback-2026-07-01` beta
and `fallbacks="default"`. Tools:

| Tool | Behaviour | Returned to Claude |
|---|---|---|
| `open_page(url)` | capture + run all checks; store PageResult | status, title, load time, counts by category/severity, top 5 finding titles, same-site links (each marked visited or not), external links (capped), pages_left |
| `check_link(url)` | status; a broken link is stored as a Finding | status |
| `screenshot(url)` | desktop + mobile PNG, attached to that page's findings | paths |
| `finish(summary)` | ends the crawl | — |

Code-enforced limits: `max_pages` (default 15), `max_steps` (60 tool calls), per-page timeout (30s).
URLs are normalized (fragment stripped, trailing slash unified), and an already-opened URL returns the
cached result without using up the budget. `open_page` is refused for other origins.
The agent takes an injected client (a real `anthropic.Anthropic` or a fake in tests) and an `on_event` callback.

Triage call: after the crawl, `triage.py` merges Findings by `id` into IssueGroups (affected URLs listed).
One Claude call with `output_config.format` (JSON schema, no tools) returns, per group id, an
`explanation` and a `fix`, plus an overall `summary`. Groups without a returned explanation keep empty text.

### scoring.py
Each category starts at 100. For each IssueGroup: subtract the base penalty (critical 25, high 10,
medium 4, low 1) × `min(1 + 0.1 × (pages_affected − 1), 2)`. Floor at 0.
Overall = mean of the category scores. Grade: A ≥ 90, B ≥ 80, C ≥ 70, D ≥ 60, else F.

### report.py + template
Writes to `reports/<domain>-<YYYYmmdd-HHMMSS>/`: `report.html`, `findings.json` (the full ScanResult) and
`screenshots/`. HTML is one self-contained file (inline CSS and JS, screenshots by relative path), with
light and dark mode. Contents:
- header with grade and 7 category score cards
- Claude's overall summary
- issues filterable by severity/category, each expandable (explanation, fix, affected pages, evidence, screenshots)
- pages table
- run details: model, input/output tokens, estimated cost, duration, partial-run flag

`site-doctor render findings.json` re-renders a report from JSON (useful for template work without the API).

### ui.py
Rich `Live` view: a header (target, model), a scrolling step log
(`[07] open_page /pricing → 200 · 1.2s · 3 issues`), and a footer with pages used / max and a severity tally.
Falls back to plain lines when stdout isn't a TTY (`--plain` forces it).

### cli.py
- `site-doctor scan URL [--max-pages 15] [--effort medium] [--model claude-opus-5-5] [--no-mobile] [--out reports] [--plain]`
- `site-doctor demo` — serves `demo_site/` on a free localhost port and scans it
- `site-doctor render FINDINGS_JSON [--out DIR]`

Missing API key → a clear message pointing to `ANTHROPIC_API_KEY`. Missing browsers → message with
`playwright install chromium`.

## Error handling

- Page load failure → a Finding (critical if it's the start URL, high otherwise); the crawl continues.
- `anthropic.APIConnectionError` / `RateLimitError` / `APIStatusError` after SDK retries, Ctrl+C, or a
  `refusal` stop reason → stop the crawl and write a **partial report** marked as such.
- Triage call failure → report written without explanations.
- Tool exceptions are returned to Claude as `is_error` tool results, never raised.

## Testing (pytest, no API key)

- `demo_site` served by a session fixture (`http.server` on a free port).
- One test module per check: the planted bug is found; `clean.html` yields no findings for that check.
  Pure checks are also tested with hand-built `PageCapture` objects.
- `test_scoring.py`: penalties, multiplier cap, floor, grades.
- `test_agent.py`: a fake client plays back scripted tool calls; asserts the page cap, step cap, URL dedupe,
  cross-origin refusal, partial report on API error, and the event sequence.
- `test_report.py`: renders a ScanResult; the HTML contains the grade, every issue and is valid UTF-8.

CI (`.github/workflows/ci.yml`): ubuntu-latest, Python 3.11/3.12/3.13, `pip install -e .[dev]`,
`playwright install --with-deps chromium`, `ruff check`, `pytest`.

## demo_site planted bugs

Broken internal and external links, a JS error, a missing alt attribute, low-contrast text, a missing meta
description, two h1s, a 2MB image shown at 200px, a layout-shift banner, a page wider than a phone
screen, tiny tap targets, and a 500 page (via a small custom handler). Plus a `clean.html` with none of these.

Hero line + badges (CI, Python, license), demo GIF (`docs/demo.gif`, recorded with `vhs demo.tape`;

## Out of scope

Web UI, authentication/logged-in crawling, scheduled scans, multiple browsers, PDF export.

## Known limits

- The demo GIF and `examples/sample-report.html` need one real run with the user's API key.
- On this machine Playwright browsers live in `D:\site-doctor\.browsers` via the user-level
  `PLAYWRIGHT_BROWSERS_PATH` variable; the package itself does not hardcode a path. The v1 env-var
  override in `site_doctor.py` is removed with that file.
